# Tableau Dashboard — Checkout A/B Test

## Business Objective

This dashboard communicates the performance and risk profile of a simplified single-page checkout relative to the existing multi-step flow. It is designed for a product decision audience and answers three questions:

1. Did treatment improve progression through the checkout funnel?
2. Did the conversion gain translate into higher retained revenue per exposed user?
3. Did payment reliability, checkout stability, or order quality materially worsen?

## Analysis Scope

- **Population:** eligible users with a first valid checkout exposure and a complete 24-hour observation window
- **Analysis unit:** one mature exposed user
- **Primary metric:** attributed purchase conversion within 24 hours
- **Ordered funnel:** `checkout_view → payment_attempt → purchase`
- **Order follow-up:** seven days for final completed, refunded, or cancelled status
- **Treatment effect:** treatment minus control

The dashboard uses simulated data only and contains no real personal information.

## Workbook

- [`checkout_ab_test_dashboard.twbx`](checkout_ab_test_dashboard.twbx) — packaged Tableau workbook containing the four analysis views and embedded extracts

## Data Model

The visualization layer uses two intentionally separate data sources:

| Data source | Grain | Purpose |
|---|---|---|
| `tableau_user_metrics.csv` | One row per mature exposed user | Conversion, segment, revenue, completion-time, and guardrail metrics |
| `tableau_funnel_summary.csv` | One row per experiment group and funnel step | Ordered cumulative funnel comparison |

The files are not joined because joining a group-step summary to a user-level table would duplicate aggregate values. Both sources are generated by [`08_tableau_data_preparation.ipynb`](../notebooks/08_tableau_data_preparation.ipynb), which reuses the canonical Day 11 SQL population and attribution logic.

## Dashboard Views

### Checkout Funnel by Experiment Variant

Compares the number of control and treatment users reaching checkout view, qualifying payment attempt, and attributed purchase. Each stage is cumulative and preserves the required event order.

### Purchase Conversion by Device

Displays descriptive purchase conversion for desktop, mobile, and tablet users within each experiment group. Device is measured at first valid exposure. The view supports diagnostic comparison but is not evidence of device-specific treatment heterogeneity.

### Retained Revenue per Exposed User

Measures final completed-order revenue across all mature exposed users, including zero for non-purchasers and for orders ultimately refunded or cancelled. This metric connects conversion performance with realized commercial value.

### Experiment Guardrails

Compares payment failure, checkout error, and refund/cancellation rates using their metric-specific denominators. The dashboard does not interpret a non-significant difference as evidence of equivalence or safety.

## Metric Definitions

| Metric | Definition | Denominator |
|---|---|---|
| Purchase conversion | Users completing an attributed purchase within 24 hours | Mature exposed users |
| Payment failure rate | Payment-attempt users with a recorded failure within 24 hours | Qualifying payment-attempt users |
| Checkout error rate | Users with an error in the first valid exposure session | Mature exposed users |
| Refund/cancellation rate | Attributed orders with final refunded or cancelled status | Attributed purchasers with mature seven-day follow-up |
| Retained revenue per exposed user | Revenue from final completed attributed orders | Mature exposed users |

## Key Findings

- Purchase conversion increased from **27.47% to 29.63%**, a **+2.16 percentage-point** absolute lift and **+7.85%** relative lift.
- The two-sided primary test produced **p = 0.0030** and a 95% confidence interval of **+0.73 to +3.58 percentage points**.
- Retained revenue per exposed user increased from **$24.52 to $26.33**.
- Payment failure decreased slightly, while checkout error and refund/cancellation point estimates increased.
- No user-type, device, or traffic-source dimension showed confirmed treatment-effect heterogeneity after multiplicity correction.

## Product Decision

**Need more data before full launch.** The conversion and retained-revenue signals are positive, but the experiment did not pre-specify non-inferiority margins for guardrails. Current checkout-error and refund/cancellation confidence intervals do not rule out practically relevant harm. A confirmatory extension should define acceptable guardrail deltas in advance and collect enough observations to evaluate them directly.

## Portfolio Positioning

The dashboard is the presentation layer of an end-to-end experiment workflow. Population construction, data-quality exclusions, event ordering, attribution, statistical inference, multiplicity control, and guardrail interpretation remain documented in the SQL and notebooks. This separation keeps the visual concise while preserving analytical traceability.
